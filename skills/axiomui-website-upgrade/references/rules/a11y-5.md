# Choose heading levels by outline, not size

- ID: a11y-5
- Category: Accessibility & inclusivity
- Tags: Accessibility, WCAG, Headings, Semantics
- URL: https://axiomui.nischal.fyi/rules/a11y-5

Choose heading levels to show how sections nest. Set the type size in CSS.

- Do: h1 Settings → h2 Billing → h3 Invoices
- Don’t: h1 Settings → h4 Billing → h4 Invoices

## Why it works

In Settings, Invoices belongs inside Billing. A screen reader’s heading list exposes that relationship when Settings is level 1, Billing is level 2 and Invoices is level 3.

- [W3C WAI · Headings](https://www.w3.org/WAI/tutorials/page-structure/headings/)
- [WCAG 2.2 · Info and relationships](https://www.w3.org/WAI/WCAG22/Understanding/info-and-relationships.html)
- [Scottish Government Design System · Typography](https://designsystem.gov.scot/styles/typography)
- [WebAIM · Screen Reader User Survey #11](https://webaim.org/projects/screenreadersurvey11/#heading)

## What breaks

When Billing and Invoices are both level 4 for their smaller type, the list skips levels 2 and 3 and presents the two as peers. Someone jumping to a level 2 section won’t find Billing.

## How to apply it

1. Inspect the rendered h1–h6 elements and any role=heading with aria-level in DOM order. Compare each level with the section the heading introduces.
2. Use native heading elements and give design system components separate heading-level and text-style props.
3. Give each subsection the next heading level, such as h3 under h2. When the subsection ends, use the level of the next section.

## Before you ship

1. Open your page’s heading list in a screen reader. Do the levels show how sections nest, as Settings (1), Billing (2) and Invoices (3) do here?
2. If the designer shrinks Billing, does it stay a level 2 heading?
3. Do sections at the same depth use the same heading level?
