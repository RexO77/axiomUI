# Interaction rule review

The 40 entries below cover the catalog’s Components, Forms, System and Accessibility categories. The review compares each summary and authored deep dive with the Do and Don’t examples in the preview source. Three lessons use timed showcases instead of static panes. WCAG success criteria specify conformance conditions. Component libraries document conventions within their own systems. Axiom’s choices about prominence, layout and change confirmation also depend on the task.

## Components

| Rule | Editorial decision and example check | Primary evidence |
| --- | --- | --- |
| comp-1 · Action hierarchy | Scope the prominent action to a task group. Publish, Preview and Discard show a meaningful hierarchy. A screen containing independent tasks can have several primary actions, and a neutral choice may have none. Remove the claim that a particular eye movement or error rate follows. | [GOV.UK button emphasis](https://design-system.service.gov.uk/components/button/) |
| comp-2 · Destructive actions | Keep the named project and Cancel action in the confirmation. Tie interruption to severity, scope and recoverability. Red is a supplementary convention. WCAG 3.3.4 offers several ways to prevent serious submission errors within its defined scope, including deletion of user-controlled stored data. | [WCAG error prevention](https://www.w3.org/WAI/WCAG22/Understanding/error-prevention-legal-financial-data.html) · [APG dialog focus guidance](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) |
| comp-3 · Nested radii | Keep the geometry for equal insets and circular arcs. The preview had a 1px border plus 8px padding, making a 9px painted-edge inset. With the padding corrected to 7px, the 12px and 4px arcs now share a center. Elliptical corners and unequal insets require separate measurements. | [CSS corner shaping](https://www.w3.org/TR/css-backgrounds-3/#corner-shaping) |
| comp-4 · Avatar shapes | Keep the mixed person/file illustration and frame the crop as a learned convention. Fluent uses square group avatars. The product must still identify the entity when a portrait fails to load or is unfamiliar. | [Fluent avatar variations](https://fluent2.microsoft.design/components/web/react/core/avatar/usage) |
| comp-5 · Modals and drawers | The six-field editor contrasts an open side panel with an intentionally cramped modal. It supports a claim about usable space and access to context. Field count alone decides neither modality nor placement. Check whether someone must merely see the background or actually interact with it. | [Fluent inline and overlay drawers](https://fluent2.microsoft.design/components/web/react/core/drawer/usage) · [APG modal behavior](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) |
| comp-6 · Errors and notifications | Retain the side-by-side placement example. The panes now use the same correction and a genuinely incomplete address. An inline message and a linked summary serve complementary navigation needs. A service failure may need persistent page-level treatment. | [GOV.UK field errors](https://design-system.service.gov.uk/components/error-message/) · [Error summaries](https://design-system.service.gov.uk/components/error-summary/) |
| comp-7 · Icon labels | Archive, Share and Delete with visible verbs illustrate the treatment. Remove claims of universally understood shapes. Keep visible identification, programmatic naming and a touchscreen user’s ability to discover meaning as separate checks. Test recognition with the intended audience before omitting visible text. | [Fluent button content and icons](https://fluent2.microsoft.design/components/web/react/core/button/usage) · [WAI button pattern](https://www.w3.org/WAI/ARIA/apg/patterns/button/) |
| comp-8 · Unavailable actions | The export pane gives the plan restriction next to the button. A tooltip on a native disabled button is unreliable as the sole explanation because the control ordinarily loses its tab stop. A permission restriction and a missing answer call for different instructions. | [GOV.UK disabled buttons](https://design-system.service.gov.uk/components/button/) · [APG disabled control focusability](https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/#focusabilityofdisabledcontrols) |
| comp-9 · Pending submission | Keep the animated pending control. Its visuals demonstrate receipt of an activation. Protecting orders against retries requires a server contract. Give an accessible status when appropriate, and distinguish acknowledged, pending, saved and failed outcomes. The showcase cannot verify duplicate protection on a server. | [Stripe idempotent requests](https://docs.stripe.com/api/idempotent_requests) · [WCAG status messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html) |
| comp-10 · Icon scale | Retain the 20/20/20 and 16/20/24 SVG sizes in this toolbar. The example establishes differences in artboard size, while optical weight varies with drawing and whitespace. Carbon publishes several sizes optimized for different text pairings. Review actual glyphs and hit boxes separately. | [Carbon icon sizing](https://www.carbondesignsystem.com/building-blocks/foundations/icons/guidelines) |
| comp-11 · Card targets | The dashed outlines illustrate whole-card and title-only targets. Removed the unmeasured 16% figure. A card with bookmarks, selection or secondary destinations needs independent controls. Use meaningful native link behavior and check whether people need to copy card content. | [HTML anchor content model](https://html.spec.whatwg.org/multipage/text-level-semantics.html#the-a-element) · [WCAG target size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) |
| comp-12 · Dismissal | Keep the visible close control, Escape and backdrop as options for the illustrated read-only shortcuts sheet. The APG recommends a visible dismissal control in a modal dialog and specifies Escape in its keyboard pattern. Outside-click depends on dismissal cost. Verify return focus and a dirty form’s dismissal path in a real dialog. | [APG modal dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) |

## Forms

| Rule | Editorial decision and example check | Primary evidence |
| --- | --- | --- |
| form-1 · Label position | The side labels in the preview have different widths and produce staggered fields. A deliberately aligned label column can work. Retain stacking as a robust default and test long translations, enlarged text and programmatic association. | [WAI labeling controls](https://www.w3.org/WAI/tutorials/forms/labels/) · [GOV.UK text input](https://design-system.service.gov.uk/components/text-input/) |
| form-2 · Persistent labels | Retain the two snapshots of the same email field. Once five characters have been entered, the placeholder-only example loses the question. A format example is acceptable in a placeholder when the field is already labeled and essential instructions remain available. | [HTML placeholder definition](https://html.spec.whatwg.org/multipage/input.html#the-placeholder-attribute) |
| form-3 · Required and optional answers | The same phone field is optional in the task but marked required in the poor example. Make that contradiction explicit. Explain the convention up front, expose actual requirements programmatically and remove the arbitrary 90% threshold. | [WAI form instructions](https://www.w3.org/WAI/tutorials/forms/instructions/) · [GOV.UK question pages](https://design-system.service.gov.uk/patterns/question-pages/) |
| form-4 · Field width | The five-digit US ZIP is a valid example of a short answer. Treat width as a visual hint and accept supported variants, including ZIP+4 where appropriate. Short design width cannot justify a global maxlength or a numeric datatype for postal codes. | [GOV.UK address field lengths and international formats](https://design-system.service.gov.uk/patterns/addresses/) |
| form-5 · Selection cardinality | One plan selected and two plans checked show the conflict clearly. A native radio group allows at most one selection and can begin unanswered. A required answer by submission is a separate decision. Explain legitimate None options. | [GOV.UK radios](https://design-system.service.gov.uk/components/radios/) · [GOV.UK checkboxes](https://design-system.service.gov.uk/components/checkboxes/) |
| form-6 · Exposed choices | Keep the three billing cycles and their visibility before opening the menu. Remove the fewer-than-five rule. Option length, comparison cost and whether someone is locating a known item affect the choice of control. A long select is an example to assess in the actual task. | [GOV.UK select usage](https://design-system.service.gov.uk/components/select/) · [GOV.UK radios](https://design-system.service.gov.uk/components/radios/) |
| form-7 · Switch semantics | The preview’s Dark mode applies immediately, while Email updates waits for Save. That difference belongs to this flow. A switch exposes binary on/off state, and its label should stay stable. The underlying service determines when a change persists. | [APG switch pattern](https://www.w3.org/WAI/ARIA/apg/patterns/switch/) · [Fluent switch guidance](https://fluent2.microsoft.design/components/web/react/core/switch/usage) |
| form-8 · Validation timing | Keep the partial “maya@” example to show why first-entry errors can be premature. Field exit is one possible checkpoint. GOV.UK specifically advises waiting for Continue or Submit in its services unless research justifies earlier feedback. Submission and server checks must work independently of blur. | [GOV.UK validation timing and server checks](https://design-system.service.gov.uk/patterns/validation/) |
| form-9 · Format hints | MM / YY describes the illustrated expiry input. Distinguish a genuine contract from formatting the product can normalize. GOV.UK’s own date research found people entering written month names, a concrete reason to accept reasonable variations. | [WAI instructions and data formats](https://www.w3.org/WAI/tutorials/forms/instructions/) · [GOV.UK date-input research](https://design-system.service.gov.uk/components/date-input/) |
| form-10 · Form order | The graphic puts stops 1 and 3 on the first visual row. That gives a demonstrable mismatch for someone scanning across the row. It provides no measured time penalty. Describe the two sequences and test meaningful focus order after reflow. Avoid assuming all people use first/last name pairs. | [WCAG focus order](https://www.w3.org/WAI/WCAG22/Understanding/focus-order.html) · [W3C personal names](https://www.w3.org/International/questions/qa-personal-names) |
| form-11 · Prefill provenance | Replaced “country from en-IN” and a system-clock default with country from a saved address and date from the itinerary. Both answers have a source relevant to this booking. WCAG 3.3.7 concerns information required again within one process, subject to exceptions. Cross-session guesses and consent are different design decisions. Browser autofill alone cannot satisfy a site’s obligation to make a previously supplied value available during the same process. | [WCAG redundant entry](https://www.w3.org/WAI/WCAG22/Understanding/redundant-entry.html) · [HTML autofill purposes](https://html.spec.whatwg.org/multipage/form-control-infrastructure.html#autofill) |
| form-12 · Success feedback | The edited name stays on screen in both panes. Align the caption to that fact and remove the claimed form reset. A short inline confirmation fits a profile edit. A completed transaction can need a persistent reference and next steps. | [WCAG status messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html) · [GOV.UK confirmation pages](https://design-system.service.gov.uk/patterns/confirmation-pages/) |

## System behavior

| Rule | Editorial decision and example check | Primary evidence |
| --- | --- | --- |
| sys-1 · Loading | Both showcase tracks wait 900ms. This demonstrates what information each treatment conveys during the same wait. A skeleton can describe expected structure, a spinner indicates activity, and a determinate indicator requires measured progress. The simulation establishes no general advantage in perceived speed. | [Carbon loading patterns](https://www.carbondesignsystem.com/building-blocks/core/patterns/loading) |
| sys-2 · Empty views | The Projects pane shows the first-use case and a creation action. A filtered list needs different copy, a load failure needs recovery, and “all caught up” can be complete without a call to action. Remove the mandatory button and unsupported abandonment prediction. | [Carbon empty states](https://www.carbondesignsystem.com/building-blocks/core/patterns/empty-states) |
| sys-3 · Target size | The 44px and 16px boxes are useful illustrations. At AA, WCAG 2.5.8 specifies a 24 × 24 CSS px size with defined exceptions, including a geometric spacing test. At AAA, 2.5.5 specifies 44 × 44 CSS px with a different exception list. Distinguish CSS pixels from native platform units and visual glyphs from pointer targets. | [WCAG minimum target size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) · [Enhanced target size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html) |
| sys-4 · Time displays | The recent activity example supports elapsed-time formatting. Extend the decision to recordkeeping, date-only values and time zones. The precise counterpart must remain accessible to keyboard and touch when it matters. ECMA-402 supplies formatting primitives without prescribing the age at which to switch formats. | [ECMA-402 RelativeTimeFormat](https://tc39.es/ecma402/#relativetimeformat-objects) · [DateTimeFormat](https://tc39.es/ecma402/#datetimeformat-objects) |
| sys-5 · Token roles | The palette → alias → component diagram shows independent control over accent and warning. Distinguish the raw value’s identity from its purpose in a component. Alias syntax is standardized by the DTCG Community Group specification, while this three-layer naming scheme remains a design-system choice. | [Design Tokens Format aliases](https://www.designtokens.org/tr/2025.10/format/#aliases-references) |
| sys-6 · Recovery | The file row now identifies Trash as the destination, alongside immediate Undo. Remove the prescribed five-second deadline and universal advice to defer server deletion. Review persistence, retention, restoration scope and discoverability after a transient notice disappears. | [WCAG error prevention](https://www.w3.org/WAI/WCAG22/Understanding/error-prevention-legal-financial-data.html) · [Timing adjustable](https://www.w3.org/WAI/WCAG22/Understanding/timing-adjustable.html) |
| sys-7 · Flow progress | “Step 2 of 4” is accurate for the illustrated fixed sequence. USWDS supports a step indicator for long, linear processes and advises against it when the number of steps can change. Drop unsupported claims about early abandonment and a universal three-step threshold. | [USWDS step indicator](https://designsystem.digital.gov/components/step-indicator/) |
| sys-8 · Keyboard interaction | The illustrated modal can legitimately use Tab, Enter and Escape. Distinguish operating a whole task by keyboard from tabbing to each child. Links, buttons and composite widgets have different standard key maps. Check focus restoration and containment in an actual dialog. | [WCAG keyboard](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html) · [APG keyboard interface](https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/) |
| sys-9 · Optimistic updates | The heart changes before a simulated sync receipt. A happy-path animation cannot prove persistence or rollback correctness. Keep low-risk reversible changes as the example. Test failed saves, rapid reversal, retries and late responses before applying this pattern to a real backend. | [React optimistic updates and error recovery](https://react.dev/reference/react/useOptimistic) |
| sys-10 · Partial failure | The image fallback and retry preserve the article context. Extend the lesson to meaningful alternatives, stable dimensions and retry safety. Decorative imagery can be silent. Financial information needs explicit unavailable states that cannot be confused with a genuine zero. | [WAI image decision tree](https://www.w3.org/WAI/tutorials/images/decision-tree/) · [Stripe retry semantics](https://docs.stripe.com/api/idempotent_requests) |
| sys-11 · Reflow | Keep 640px and 1024px as the thresholds drawn in this diagram. They illustrate one design, with no implication that all tablets or desktops fit those tiers. Test between thresholds, within embedded containers and under text enlargement. | [Responsive design media queries](https://web.dev/learn/design/media-queries) · [WCAG reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) |
| sys-13 · Transition scope | CSS transitions operate on eligible changes in computed property values. Replaced the font-swap scenario with an explicit width change. The faded outlines are a diagram of interpolation, and the labels identify the intended 150ms example. | [CSS Transitions starting conditions](https://www.w3.org/TR/css-transitions-1/#starting) · [Transition property selection](https://www.w3.org/TR/css-transitions-1/#transition-property-property) |
| sys-14 · Performance hints | CSS excludes “all” from the permitted custom identifiers for will-change. The poor example previously presented invalid syntax as a working blanket hint. Both panes now show the same valid hint, scoped to one illustrated card or to every card. Confirming an optimization requires a representative trace on target hardware. | [CSS Will Change grammar and implementation guidance](https://www.w3.org/TR/css-will-change-1/#will-change) |

Separate AA focus visibility and non-text contrast from AAA focus-appearance metrics. Also test reverse navigation past sticky regions. ## What still needs observation

The previews illustrate design choices and several deliberately use noninteractive markup inside a comparison frame. This review did not collect comparative task times, error rates, screen-reader recordings, real-device touch traces or backend responses. When an implementation depends on one of those outcomes, the relevant trial is specific: try the currency- or date-format variants the product actually accepts, restore a deleted record with its prior permissions, force a request to fail after a rapid second action, or tab through the shipped dialog in forced colors. A static preview cannot answer those questions by itself.

## Related reading across the catalog

Reviewing the revised text exposed a second editorial decision. The previous recommendations awarded points for shared tags and words, then favored candidates from other categories. After the rewrite, the typeface lesson linked to stacking contexts, radio groups linked to timestamp formatting, and easing linked to nested corner radii. A motion lesson about adjusting exit timing had only one recommendation, about validating an email address. Those pairs shared vocabulary without sharing a decision readers needed to make.

The new reading sequences cover all 105 rule IDs. Each link supplies a constraint, an alternative or the next decision in the same task. Selecting a plan leads to comparing exposed choices and distinguishing switches from checkboxes. Permanent deletion leads to recovery and dismissal safeguards. The stacking-context lesson leads to surfaces, modal dismissal and the stacking side effects of performance hints. Some related lessons are in the same domain. The number of links depends on how many destinations have a concrete connection.

The tests check every source and destination ID, preserve authored order, and reject duplicate, self and dangling links. Worked examples check deletion and recovery in both directions, while regression cases cover the misleading word matches above. This verifies the authored navigation graph. It does not measure which links a reader will follow.
